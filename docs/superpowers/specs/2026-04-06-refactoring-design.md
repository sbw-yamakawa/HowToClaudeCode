## 概要

「難易度順（00〜06）」の7ファイル構成を「ユーザーのやりたいこと順」の5ファイル構成に再編する。
あわせて、「設定はClaude Codeに書かせる」を基本方針とし、各設定ファイルの仕組み解説を組み込む。

---

## 設計方針

### 1. ゴール指向の情報構造
読者が「今自分がやりたいこと」のファイルを開けば、そこに完結した情報がある。

### 2. 「Claudeに書かせる」を先に示す
設定作業は「Claudeに頼む」を基本フローとして先に説明し、その後「何が書かれているか」の解説を添える。JSONを手書きさせるよりも先にClaudeへの指示例を示す。

### 3. 対象読者
完全初心者〜中級者（現状維持）。各ファイルは独立して参照できる。

### 03-better-prompts.md「より正確に動かしたい」

**統合元:** `02-intermediate.md`（プロンプト術セクション + /branch セクション）

**構成:**
```
## 良いプロンプトの4原則
  - 具体的に書く（悪い例/良い例）
  - コンテキストを与える
  - 制約を明示する
  - 大きなタスクは分割する
## 複数アプローチを探索する（/branch）
```

**注意:** トラブルシューティングは「起動時」と「使用時」で分割。起動時は `01-getting-started.md`、使用時はここ。

### 04-customize.md「自分仕様に設定したい」

**統合元:** `02-intermediate.md`（CLAUDE.md・settings・rules/ セクション）+ `05-dotfiles.md`

**「Claudeに書かせる」方針の実装例:**

各セクションで「Claudeへの指示例」を先に示し、その後「何が書かれているか」を解説する。

```
# 例: MCPフックの設定
❌ 従来: settings.jsonのhooksセクションにJSONを手書き
✅ 新方針:
  > ファイルを保存するたびにlintを自動実行するフックを設定してください
  （→ Claudeがsettings.jsonを読んで追記）
  （→ 追記された内容の仕組みを解説）
```

**構成:**
```
## CLAUDE.md — プロジェクトのルールを設定する
  /init でClaudeに生成させる（推奨フロー）
  → 生成されたファイルの読み方・編集方法（何が書かれているか解説）
  → 効果的なCLAUDE.mdの書き方（プロジェクト固有情報に絞る）

## ~/.claude/rules/ — 全プロジェクト共通ルール
  Claudeに書かせる指示例
  → rulesディレクトリの仕組み解説
  → カテゴリ別分割パターン

## 設定ファイル（settings.json）
  /config でインタラクティブに設定する（推奨フロー）
  → 設定の3スコープ解説（グローバル・プロジェクト・ローカル）
  → 主要設定項目（モデル・Output style等）の解説

## フック — ツール実行前後に自動処理
  Claudeにフックを設定させる指示例
  → フックの仕組み解説（PreToolUse / PostToolUse）
  ※ フックは「設定」の一部としてここに移動（現在は03-advanced.md）

## dotfiles — チームで設定を共有する
  Claudeにsetup.shを書かせる
  → シンボリックリンクの仕組み解説
  → インポートできる内容（rules / agents / skills / settings.json）
```

### 05-extend.md「できることを増やしたい」

**統合元:** `03-advanced.md` + `06-extensions.md`（重複除去）

**重複除去の方針:**
- MCP概念説明：1か所にまとめる（現在 03 と 06 の両方に記載）
- サブエージェントの仕組み説明：1か所にまとめる（現在 03 と 06 の両方に記載）
- 削除見込み：約150〜200行

**構成:**
```
## 拡張機能の全体像（4種類の早見表）
  MCPサーバー / スキル / エージェント / プラグイン

## MCPサーバー — 外部ツールを繋げる
  Claudeに設定させる（推奨フロー）:
    > GitHubのIssueを操作したい。適切なMCPを探して設定してください
  → 仕組み解説（settings.jsonのmcpServersに何が書かれるか）
  → 代表的サーバー一覧（Playwright / GitHub / context7 / serena）
  → 手動追加方法（CLIコマンド・JSON直編集）は補足

## スキル — /コマンドを作る
  Claudeにスキルファイルを書かせる:
    > /commit スキルを作ってください。git規約コミットを自動化したい
  → スキルファイルの構造解説（frontmatterの意味）
  → 活用例（/handover / /security-review）

## エージェント — 専門家の役割を定義する
  Claudeにエージェントファイルを書かせる:
    > sql-reviewer エージェントを作ってください
  → エージェントファイルの構造解説（descriptionの重要性・自動起動の仕組み）
  → チームパターン（planner → tdd-guide → code-reviewer のパイプライン）
  → 定義あり vs 定義なし（自律）の使い分け

## プラグイン — まとめてインポートする
  → 探し方・インポート方法
  → superpowers / serena / context7 の紹介
```

**注意:** フック（Hooks）は `04-customize.md` に移動。拡張機能というより設定の一部のため。
