# 毎日の使い方

## 基本操作

### 起動と終了

```bash
claude       # プロジェクトディレクトリで起動
/exit        # または Ctrl+C で終了
```

### よく使うコマンド

| コマンド | 説明 |
|---------|------|
| `/help` | コマンド一覧 |
| `/clear` | 会話履歴をリセット |
| `/compact` | 長い会話を要約してコンテキストを節約 |
| `/cost` | 現在の会話コストを表示 |
| `/status` | モデルや設定を確認 |
| `/rewind` | 同じセッション内で過去の状態に巻き戻す |
| `/resume` | 別のセッションに切り替えて再開する |
| `/exit` | 終了 |

### よく使うショートカットキー

| キー | 説明 |
|------|------|
| `Ctrl+C` | 現在の入力・レスポンスをキャンセル |
| `Ctrl+D` | セッションを終了 |
| `↑` / `↓` | コマンド履歴をナビゲート |
| `Ctrl+R` | コマンド履歴を逆検索 |
| `Shift+Enter` / `\ + Enter` | 複数行入力（Enterで送信せず改行） |
| `Esc Esc` | `/rewind` メニューを開く |
| `Shift+Tab` | パーミッションモードを切り替え |
| `Alt+T` | 拡張思考（Extended Thinking）をトグル |
| `Ctrl+O` | ツール実行の詳細出力をトグル |

## 話しかけ方のコツ

`>` プロンプトに日本語で入力するだけ。

```
> README.mdを読んで、このプロジェクトが何をするものか教えてください
> src/index.tsにバグがあります。確認してください
> テストを実行して結果を教えてください
```

具体的に指示するほど精度が上がる。「直して」より「○○というエラーが出るので修正して」の方がいい。

詳しいプロンプトの書き方は [03-better-prompts.md](./03-better-prompts.md) を参照。

## よくある作業パターン

コピペして使えるプロンプト例。

### ファイルを読ませる・編集させる

```
> src/utils.tsを読んで、どんな関数があるか説明してください
> src/auth.tsとsrc/user.tsを読んで、認証の流れを説明してください
```

```
> src/utils.tsのformatDate関数にタイムゾーン対応を追加してください
> package.jsonにlintスクリプトを追加してください: "lint": "eslint src/**/*.ts"
```

変更前に確認が入る（`y` で承認、`n` でスキップ）。

### コマンドを実行させる

```
> npm testを実行して、失敗しているテストを教えてください
> git statusの結果を見て、コミットするべき変更をまとめてください
```

### コーディング

**コードを生成する**

```
> TypeScriptで以下の関数を実装してください:
> - 関数名: formatCurrency
> - 引数: amount (number), currency (string, デフォルト "JPY")
> - 戻り値: "¥1,000" のようにフォーマットされた文字列
> - Intl.NumberFormatを使うこと
```

**バグを修正する**

```
> 以下のエラーが発生しています:
> TypeError: Cannot read properties of undefined (reading 'map')
> src/components/UserList.tsx の34行目です。
>
> エラーが発生する条件と修正方法を教えてください。
```

**コードレビュー**

```
> src/services/payment.tsをレビューしてください。
> 特にエラーハンドリングとセキュリティ面で問題がないか確認してください。
```

**リファクタリング**

```
> src/utils/date.tsをリファクタリングしてください。
> - 重複ロジックを共通化する
> - 関数名をより分かりやすくする
> - 型定義を厳密にする
> 既存のテストが通ることを確認しながら進めてください。
```

**テストを書く**

```
> src/services/auth.tsのlogin関数のユニットテストをVitestで書いてください。
> - 正常系: 正しい認証情報でトークンが返る
> - 異常系: パスワード間違いで401エラー
> - 異常系: ユーザーが存在しない場合
```

**影響範囲を調べる**

```
> src/api/orders.tsを修正する前に、このファイルを参照しているファイルを調べて
> 変更の影響範囲を教えてください。
```

### ドキュメント作成

**READMEを書く**

```
> このプロジェクトのREADMEを日本語で書いてください。
> 含めてほしい内容: プロジェクト概要・主な機能・インストール手順・使い方・環境変数一覧
```

**JSDocコメントを補完する**

```
> src/services/以下の全ファイルのpublic関数にJSDocコメントを日本語で追加してください。
> 既存のコメントは変更しないでください。
```

**API仕様書を書く**

```
> src/api/users.tsのエンドポイント一覧から、API仕様書をMarkdown形式で作成してください。
> 各エンドポイントについて: HTTPメソッドとパス・リクエストパラメータ・レスポンス・エラーレスポンス
```

**パワーポイント資料を作る**

```
> /pptx
>
> 以下の内容でプレゼン資料を作成してください。
> - テーマ: 新機能のリリース概要
> - スライド数: 8枚程度
> - 構成: タイトル・背景・課題・解決策・主な機能3つ・まとめ
> - 対象: 社内の非技術系ステークホルダー
> - カラーテーマ: ネイビー×ホワイト系でプロフェッショナルな印象に
```

既存のPPTXを分析・編集する場合:

```
> /pptx
>
> template.pptxを分析して、以下の変更を加えてください。
> - タイトルスライドの会社名を "Acme Corp" に更新
> - スライド3のグラフデータを最新の数値に差し替え
> - フォントをCalibriに統一する
```

**PRの説明文を書く**

```
> git diff main...HEADの変更内容を確認して、
> プルリクエストの説明文を日本語で書いてください。
> 変更の背景・内容・テスト方法を含めてください。
```

**コードを説明してもらう**

```
> src/middleware/rateLimit.tsの処理を説明してください。
> レート制限のアルゴリズムと、設定値の意味を教えてください。
```

### ルールを書かせる

**CLAUDE.md を生成する**

```
> /init
```

プロジェクトを自動解析して CLAUDE.md を生成する。生成後に不要な項目を削除したり、チーム固有のルールを追記する。

**会話から学んだことをルールに反映させる**

セッション中に「毎回伝えなければいけない」と気づいたことをそのままルール化させる。

```
> いま指摘してくれた「Result型でエラーを返す」パターンを、
> このプロジェクトの全員が守れるよう CLAUDE.md のコーディングルールに追加してください。
```

```
> 今回の会話で決まったことを CLAUDE.md にまとめてください。
> 次回以降も同じ前提で進められるようにしてください。
```

**~/.claude/rules/ のルールを書かせる**

自分のコーディングの癖や好みを言葉にして渡すと、ルールファイルとして整理してくれる。

```
> 私のコーディングスタイルを ~/.claude/rules/coding-style.md にまとめてください。
> 好み:
> - イミュータブルなコードを書きたい（オブジェクトを直接変更しない）
> - 関数は短く（50行以内）
> - TypeScript の any は絶対に使わない
> - エラーは例外ではなく戻り値で返す（Result型）
```

**既存コードからルールを逆生成する**

すでに書いたコードを分析させてルールを抽出させることもできる。

```
> src/ 以下のコードを読んで、このプロジェクトで使われているコーディングパターンを
> 分析してください。そのうえで CLAUDE.md のコーディングルールセクションを書いてください。
```

**ルールを定期的に見直す**

```
> CLAUDE.md を読んで、古くなっている・実態と合っていないルールがあれば指摘してください。
> 最近の実装と照らし合わせて確認してください。
```

### その他

**環境構築を手伝ってもらう**

```
> このプロジェクトをローカルで動かすためのセットアップ手順を教えてください。
> 必要な環境変数と、その取得方法も含めてください。
```

**テストの失敗を調べる**

```
> npm testを実行してください。失敗しているテストがあれば、
> 原因と修正方法を説明してください。
```

**技術的な質問をする**

```
> このプロジェクトのキャッシュ戦略について教えてください。
> どこでキャッシュが使われていて、TTLはどう設定されていますか？
```

## セッション管理

新しいタスクを始めるときは `/clear` でリセット。古い会話が残っていると混乱することがある。

### /rewind — 同じセッション内で巻き戻す

`Esc Esc` または `/rewind` で過去のチェックポイント一覧を表示。選択後に操作を選ぶ：

| 操作 | 説明 |
|------|------|
| Restore code and conversation | コードと会話の両方を巻き戻す |
| Restore conversation | 会話だけ戻す（コードはそのまま） |
| Restore code | コードだけ戻す（会話はそのまま） |
| Summarize from here | その地点以降の会話を圧縮してコンテキストを解放 |

**注意**: Bash コマンドによるファイル変更（`rm`, `mv` など）は追跡されない。

### /resume — 別のセッションを再開する

```bash
claude --continue          # 最新のセッションを再開
claude --resume            # セッション一覧から選んで再開
claude --resume <名前>     # 名前を指定して再開
```

セッション内でも `/resume` で別の会話に切り替えられる。

### 使い分け

| やりたいこと | コマンド |
|-------------|---------|
| 直近の変更を取り消して別の方法を試す | `/rewind` |
| 前回の作業の続きから始める | `/resume` または `claude --continue` |
| 機能Aの作業中に機能Bへ切り替える | `/resume` |
