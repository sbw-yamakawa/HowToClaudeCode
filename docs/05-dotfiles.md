# 05. dotfiles で Claude Code をカスタマイズする

このドキュメントでは、配布している dotfiles リポジトリをインポートすることで使えるようになる機能を説明します。

---

## セットアップ方法

```bash
git clone <dotfiles-repo-url>
cd dotfiles
bash setup.sh
```

スクリプトを実行すると、以下の設定が `~/.claude/` にシンボリックリンクとして配置されます:

| リンク先 | 内容 |
|---------|------|
| `~/.claude/rules/` | AIの振る舞いを定義するルール |
| `~/.claude/agents/` | カスタムエージェント定義 |
| `~/.claude/skills/` | スラッシュコマンドで呼び出せるスキル |
| `~/.claude/plugins/` | インストール済みプラグイン設定 |
| `~/.claude/settings.json` | Claude Code 全体の設定 |

---

## 1. ルール（Rules）— AIの振る舞いを統一する

`~/.claude/rules/` に置いたMarkdownファイルは、すべてのプロジェクトで自動的に適用されます。
「毎回同じ指示を書かなくていい CLAUDE.md」として機能します。

### 含まれるルール

#### `agents.md` — エージェント自動起動ルール

コードを書いたら自動でレビュー、複雑なタスクには自動でプランナーを起動するよう指示します。

```
複雑な機能リクエスト → planner エージェントを自動起動
コード変更直後     → code-reviewer エージェントを自動起動
バグ修正・新機能   → tdd-guide エージェントを自動起動
```

#### `coding-style.md` — コーディングスタイル

イミュータビリティ、ファイルサイズ制限、セキュリティチェックリストなどを定義します。

```
- オブジェクトは常に新規作成（ミューテーション禁止）
- ファイルは200〜400行、最大800行
- コミット前のセキュリティチェック必須
```

#### `git-workflow.md` — Gitワークフロー

コミットメッセージのフォーマットとPR作成手順を定義します。

```
形式: <タイプ>: <説明>
タイプ: feat, fix, refactor, docs, test, chore, perf, ci
```

#### `verification.md` — 検証戦略

実装完了の基準と検証手順を定義します。テストカバレッジ80%以上を要求します。

---

## 2. カスタムエージェント（Agents）— 専門家を自動で召喚する

`~/.claude/agents/` に置いたMarkdownファイルがサブエージェントとして使えます。
Claude Code が適切なタイミングで自動的に起動します。

### 含まれるエージェント

| エージェント | 役割 | 自動起動のタイミング |
|-------------|------|-------------------|
| `planner` | 実装計画・アーキテクチャ設計 | 複雑な機能リクエスト時 |
| `tdd-guide` | テスト駆動開発の実践 | 新機能追加・バグ修正時 |
| `code-reviewer` | コード品質レビュー | コード変更直後 |
| `security-reviewer` | セキュリティ脆弱性の検出 | コミット前 |
| `build-error-resolver` | ビルド・型エラーの修正 | ビルド失敗時 |
| `e2e-runner` | Playwright E2Eテストの実行 | 重要なユーザーフロー確認時 |
| `refactor-cleaner` | 不要コードの削除 | コードメンテナンス時 |

### 使用例

```
> 認証システムを実装したい

→ planner エージェントが自動起動して実装計画を作成
→ tdd-guide エージェントがテストを先に書く
→ code-reviewer エージェントが実装後にレビュー
→ security-reviewer エージェントが認証コードをセキュリティチェック
```

### 各エージェントの詳細

**planner** — Opus モデルで動作する設計専門エージェント
- 要件分析 → 複数の設計案提示 → 実装フェーズの計画作成
- コードに触れる前にユーザー確認を待つ

**tdd-guide** — RED→GREEN→REFACTOR サイクルで実装
- テストを先に書いてから実装
- 80%以上のカバレッジを確保

**code-reviewer** — 品質・セキュリティ・保守性をレビュー
- 書いたコードをすべてレビュー対象にする

**security-reviewer** — OWASP Top 10 をカバー
- シークレット漏洩、SQLインジェクション、XSS などを検出

**build-error-resolver** — 最小差分でビルドエラーのみを修正
- アーキテクチャ変更を行わず、素早くビルドをグリーンにする

## 3. スキル（Skills）— スラッシュコマンドで専門ワークフローを呼び出す

`/スキル名` で呼び出せるカスタムスラッシュコマンドです。

### 含まれるスキル

#### `/commit` — 規約に沿ったコミット作成

```
> /commit
```

staging されたファイルを確認して、規約に沿ったコミットメッセージを提案・実行します。

#### `/handover` — セッション引き継ぎドキュメント作成

```
> /handover
```

現在の作業状況、決定事項、次のアクションをまとめたドキュメントを自動生成します。
長いセッションを別のセッションに引き継ぐときに使います。

#### `/tdd-workflow` — TDD 原則の参照

```
> /tdd-workflow
```

RED→GREEN→REFACTOR サイクルの原則とチェックリストをコンテキストに注入します。

#### `/security-review` — セキュリティチェックリスト

```
> /security-review
```

認証・SQL インジェクション・XSS・シークレット管理など、包括的なセキュリティチェックリストを適用します。

#### `/pptx` — PowerPoint ファイルの作成・編集

```
> /pptx
```

PowerPoint ファイルの作成・編集を支援します（pptxgenjs を使用）。

## 4. プラグイン（Plugins）— 外部ツール連携

セットアップスクリプトが自動でインストールするプラグインです。

### 含まれるプラグイン

| プラグイン | 機能 |
|----------|------|
| **superpowers** | スキルシステム（スラッシュコマンド）を有効化 |
| **serena** | コードのシンボル解析・セマンティック検索 |
| **github** | GitHub Issues/PR の操作 |
| **playwright** | ブラウザ自動操作・スクリーンショット |
| **context7** | ライブラリの最新ドキュメントを自動取得 |

### 使用例

**serena** — ファイル全体を読まずにシンボル単位でコード理解

```
> UserService クラスの認証メソッドを修正してください
（ファイル全体ではなく、対象メソッドだけを読んで効率的に修正）
```

**context7** — 最新ライブラリドキュメントの自動参照

```
> Next.js の App Router でミドルウェアを設定してください
（学習データに頼らず、最新の公式ドキュメントを参照して回答）
```

**playwright** — ブラウザ操作の自動化

```
> localhost:3000 を開いてログインフローをテストしてください
```

**github** — GitHub 操作

```
> issue #42 の内容を確認して、対応するコードを修正してください
```

## 5. 設定（settings.json）— 動作をカスタマイズ

### 主な設定内容

#### 許可済みコマンド（確認プロンプトなしで実行）

```json
"permissions": {
  "allow": [
    "Bash(git checkout:*)",
    "Bash(git commit:*)",
    "Bash(git push:*)",
    "Bash(npm:*)",
    "Bash(node:*)"
  ],
  "defaultMode": "dontAsk"
}
```

よく使うコマンドを事前に許可することで、作業の流れを止めずに進められます。

#### タイムスタンプ自動挿入フック

```json
"hooks": {
  "UserPromptSubmit": [
    {
      "hooks": [{ "type": "command", "command": "bash ~/.claude/scripts/inject-timestamp.sh" }]
    }
  ]
}
```

プロンプト送信時に現在時刻を自動で挿入します。
「今日」「明日」「来週」などの相対的な表現を正確に解釈させるためのフックです。

#### カスタムステータスライン

```json
"statusLine": {
  "type": "command",
  "command": "bash ~/.claude/statusline-command.sh"
}
```

入力欄の上に以下の情報をリアルタイム表示します:

```
So4.6 │ +12/-3 │ feature/auth │ myproject
ctx ▊▊▊░░ 35% │ 5h ████░ 52% │ 7d ██░░░ 23%
```

- 使用中のモデル名（短縮表示）
- 変更行数（追加/削除）
- Gitブランチ名
- コンテキスト使用率とレートリミット残量

#### 日本語設定

```json
"language": "Japanese"
```

すべての応答を日本語で返すよう設定されています。

#### 実験的なエージェントチーム機能

```json
"env": {
  "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
}
```

複数のエージェントをチームとして協調動作させる実験的機能を有効化します。

---

## まとめ: dotfiles が解決すること

| 課題 | 解決策 |
|------|--------|
| 毎回同じ指示を書く手間 | Rules で永続的な指示を設定 |
| コードレビューを忘れる | Agents が自動でレビューを実行 |
| テストを後回しにしてしまう | tdd-guide エージェントが先にテストを書く |
| よく使う操作に毎回許可が必要 | permissions で事前許可リストを設定 |
| 「今日」の日付をAIが誤解する | フックで現在時刻を自動注入 |
| ライブラリの古い情報で回答される | context7 プラグインで最新ドキュメントを参照 |
