# 自分仕様に設定する

Claude Code は設定ファイルを自分で読み書きできる。手で JSON を書く前に、まず Claude に頼んでみる。

---

## CLAUDE.md — プロジェクトのルールを設定する

### Claudeに生成させる（推奨）

プロジェクトのルートで `/init` を実行すると、Claude がコードベースを解析して CLAUDE.md を生成する。

```
> /init
```

プロジェクトを自動解析して CLAUDE.md の初期テンプレートを生成してくれる。手動で一から書くより、既存コードベースの構成・使用技術に合った内容が得られる。生成後は不要な項目を削除し、チーム固有のルールを追記するだけでよい。

### CLAUDE.md でできること

プロジェクトルートに置くと起動時に自動で読み込まれる。毎回同じ指示を書かなくて済む。

**サブディレクトリにも置ける**

```
your-project/
  CLAUDE.md          # プロジェクト全体のルール
  src/
    CLAUDE.md        # srcディレクトリ固有のルール（任意）
```

**効果的な CLAUDE.md の書き方**

プロジェクト固有の情報に絞る。どのプロジェクトでも同じルール（コーディングスタイル、コミット形式など）は `~/.claude/rules/` に書く。CLAUDE.md はこのプロジェクトだけに必要な情報を書く場所。

```markdown
# CLAUDE.md に書くべきもの
- 技術スタックとバージョン（Next.js 14 + Prisma 5.x）
- ディレクトリ構成の概要
- よく使うコマンド
- プロジェクト固有のルール（エラーハンドリングの方式など）
- 地雷情報（本番DBには繋がない、など）

# ~/.claude/rules/ に書くもの（CLAUDE.md に書かない）
- コーディングスタイル全般
- コミットメッセージのフォーマット
- テストカバレッジの基準
```

「どこを見ればわかるか」を書く。実装パターンやアーキテクチャの詳細を全部書くより、参照先を示すほうが効果的。

```markdown
## アーキテクチャ

- APIルート: `src/app/api/` 以下（App Router）
- DBアクセス: Prisma経由のみ（生SQLは禁止）
- 認証: `src/lib/auth.ts` を参照
- エラーハンドリング: `src/types/result.ts` の Result 型パターンを使う
```

禁止事項は理由とセットで書く。理由がないと、Claude が例外ケースを判断できない。

```markdown
# 良い例
- `any` は使わない（型安全性が失われ、バグの温床になるため）
- 本番DBに直接繋がない（開発中の誤操作で本番データを破壊するリスクがある）
  → ローカルでは docker-compose up で起動したDBを使う
```

## ~/.claude/rules/ — 全プロジェクト共通ルール

### Claudeに書かせる

```
> 私のコーディングスタイルを ~/.claude/rules/coding-style.md にまとめてください。
> イミュータブルなコード・関数は50行以内・TypeScriptのanyは使わない
```

Claude が `~/.claude/rules/` にファイルを作成し、内容を書いてくれる。あとは自分の好みに合わせて編集するだけ。

### 仕組み

`~/.claude/rules/` に Markdown ファイルを置くと、**すべてのプロジェクトで自動的に読み込まれる**。

| | CLAUDE.md | ~/.claude/rules/ |
|---|---|---|
| スコープ | そのプロジェクトのみ | 全プロジェクト共通 |
| 用途 | プロジェクト固有のルール | 自分のコーディングスタイル・習慣 |
| Gitで管理 | する（チームと共有） | しない（個人設定） |

**カテゴリ別に分割する**

1つのファイルにまとめるより、テーマ別に分割するほうが管理しやすい。

```
~/.claude/rules/
  coding-style.md    # コーディングスタイル
  git-workflow.md    # コミットメッセージ・PRの作り方
  agents.md          # エージェントをいつ使うかのルール
  verification.md    # テスト・検証の基準
```

**効果的なルールの書き方**

「何をするか」より「なぜするか」を書く。トリガー条件も明示しておくと精度が上がる。

```markdown
## コミット前チェック（コミット操作のたびに必ず確認）
- [ ] ハードコードされたシークレットがない
- [ ] console.log が残っていない

## セキュリティ問題を見つけたとき（即座に停止して対処）
1. 作業を止める
2. security-reviewer エージェントを呼ぶ
3. 修正してから次に進む
```

## 設定ファイル（settings.json）

### /config でインタラクティブに設定する（推奨）

セッション中に `/config` を実行するとインタラクティブなメニューが開く。変更内容は自動で `~/.claude/settings.json` に保存される。

```
/config
```

メニューから選ぶだけで設定が保存される。JSON を直接編集する必要はない。

### Claudeに設定させる

```
> ファイルを保存するたびに lint を自動実行するフックを設定してください
```

Claude が `settings.json` を読んで適切に追記する。フックの書き方を覚えなくてよい。

### 設定の3スコープ

設定は JSON ファイルで管理する。スコープが3段階あり、後から読まれるものが優先される。

| ファイル                      | スコープ             | 用途                              |
| ----------------------------- | -------------------- | --------------------------------- |
| `~/.claude/settings.json`     | グローバル           | 全プロジェクト共通の個人設定      |
| `.claude/settings.json`       | プロジェクト         | チーム共有設定（コミット対象）    |
| `.claude/settings.local.json` | プロジェクトローカル | 個人用の上書き（.gitignore 推奨） |

### 主な設定項目

`/config` で変更できる主な設定:

| 設定           | 内容                              |
| -------------- | --------------------------------- |
| モデル         | opus / sonnet / haiku の切り替え  |
| 努力レベル     | low / medium / high（推論の深さ） |
| テーマ         | ターミナルの表示テーマ            |
| エディタモード | Vim モードの有効/無効             |
| 言語           | UI・応答言語                      |
| Output style   | Claudeの応答スタイル（後述）      |

**Output style**

Claude の応答形式を切り替える機能。ビルトインスタイルが3種類用意されている。

| スタイル      | 特徴                                                                        |
| ------------- | --------------------------------------------------------------------------- |
| `Default`     | 標準のコーディング向けスタイル                                              |
| `Explanatory` | 実装の要所に Insight を挿入して教育的に説明する                             |
| `Learning`    | Claudeが `TODO(human)` を残し、実装の一部をユーザーに委ねる対話型学習モード |

## フック — ツール実行の前後に自動処理

### Claudeにフックを設定させる

```
> ファイルを編集するたびに自動でlintを実行するフックを追加してください
```

Claude が `settings.json` の `hooks` セクションに適切なエントリを追記する。フックのイベント名やマッチャーの書き方を覚えなくてよい。

### 仕組み

Claude Code がツールを実行する前後に、自動でコマンドを走らせる仕組み。

`.claude/settings.json` の `hooks` セクションに書く:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          { "type": "command", "command": "npm run lint -- --fix" }
        ]
      }
    ]
  }
}
```

**イベントの種類**

| イベント     | タイミング             |
| ------------ | ---------------------- |
| `PreToolUse` | ツール実行の直前       |
| `PostToolUse`| ツール実行の直後       |

**matcher でツールを絞り込む**

`matcher` に正規表現を書くことで、特定のツールにだけフックを適用できる。

```json
"matcher": "Write|Edit"   // ファイル書き込み・編集時のみ
"matcher": "Bash"         // Bash コマンド実行時のみ
```

**コマンド実行前にログを記録する例**

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "echo '[Hook] Bash実行前' >> .claude/log.txt" }
        ]
      }
    ]
  }
}
```

## dotfiles — チームで設定を共有する

### Claudeにsetup.shを書かせる

```
> チームのClaude Code設定をdotfilesで共有したい。
> rules/とagents/をシンボリックリンクで管理するsetup.shを作ってください
```

Claude が dotfiles リポジトリの構成を提案し、setup.sh を作成してくれる。

### 仕組み

dotfiles リポジトリをインポートすることで、チームの設定を共有できる。

```bash
git clone <dotfiles-repo-url>
cd dotfiles
bash setup.sh
```

`setup.sh` が `~/.claude/` 以下にシンボリックリンクを配置する:

- `~/.claude/rules/` — AIの振る舞いを定義するルール
- `~/.claude/agents/` — カスタムエージェント定義
- `~/.claude/skills/` — スラッシュコマンドで呼び出せるスキル
- `~/.claude/plugins/` — インストール済みプラグイン設定
- `~/.claude/settings.json` — Claude Code 全体の設定

**インポートできる内容**

| 種類 | 場所 | 効果 |
|------|------|------|
| ルール | `~/.claude/rules/` | 全プロジェクトで自動適用 |
| エージェント | `~/.claude/agents/` | 適切なタイミングで自動起動 |
| スキル | `~/.claude/skills/` | `/スキル名` で呼び出し可能 |
| 設定 | `~/.claude/settings.json` | Claude Code 全体の動作を制御 |

シンボリックリンクで管理するため、dotfiles リポジトリを更新するだけでチーム全員の設定が同期される。
